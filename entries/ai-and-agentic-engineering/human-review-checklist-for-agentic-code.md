# The Human Review Checklist for Agentic Code & Preventing Code Slop

## 🔍 Context & Scenario
As AI coding agents (such as Antigravity, Claude Code, Cursor) become the primary generators of application code and test suites, development velocity increases 10x. However, agents exhibit a well-known pathological tendency: they will happily generate 400 lines of code and passing mock tests that violate core business invariants or introduce redundant "code slop".

## 💥 The Incident & Pitfalls of Agent-Generated Code
1. **Passing Tests That Assert Nothing Real**: Agents frequently generate unit tests that mock the entire universe, asserting that their mock returns mock data, giving a false sense of 100% green tests.
2. **Authorization & RBAC Invariant Bypass**: Agents often write endpoints that perform complex domain logic but forget basic tenant scoping or authentication checks (`WHERE user_id = current_user`).
3. **Ghost Feature Creep / Code Slop**: When prompted to fix a small UI glitch, agents may rewrite whole state stores, introduce unnecessary helper abstractions, or duplicate existing utility functions.

## 🛠️ The Core Antigravity Human Review Checklist

Whenever reviewing Pull Requests or diffs generated by AI agents, every engineer must verify these four non-negotiable gates:

### Gate 1: Business Invariants & Domain Integrity
- [ ] **State Machine Validity**: Does the code allow illegal state transitions (e.g. paying for an already cancelled order, enrolling in an unpublished course)?
- [ ] **Temporal Boundaries**: Are timestamps, start/end dates, and causality strictly respected?
- [ ] **Idempotency**: What happens if an API call is retried 3 times due to a network blip?

### Gate 2: Authorization & Boundary Isolation
- [ ] **Tenant & User Scoping**: Is data strictly scoped to the requesting identity at the database query level, rather than filtered in frontend memory?
- [ ] **Role Invariants**: Are actions restricted by role (e.g., in `ai-directed-learning`, students can `View`, while only tutors can `Edit/Delete`)?

### Gate 3: Anti-"Code Slop" Filter
- [ ] **Redundant Helpers**: Did the agent reinvent a utility that already exists in the codebase?
- [ ] **Over-Engineering**: Did a 3-line bug fix turn into a 150-line generic abstraction layer?
- [ ] **Unused Imports & Dead Code**: Remove any exploratory scaffolding or unreferenced interfaces.

### Gate 4: Test Realism
- [ ] **No Hollow Mocks**: Are tests hitting real integration points or testing real invariant violations (e.g. asserting `403 Forbidden` when an unauthorized user attempts an action)?
- [ ] **Regression Assertion**: Does at least one test fail if the fix is removed?
